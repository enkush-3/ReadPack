# Plugin: Dynamic Issue-Driven Agent Spawner (with Parallel Execution)

## ЗАРЧИМ
Энэхүү плагин нь хатуу урьдчилан бэлдсэн бүтэц ашиглахгүй. Шүүмжид тусгагдсан асуудлуудыг шинжилж, яг тэр асуудлыг шийдэх тусгай агентуудыг тодорхойлно. Үүний дараа хамааралгүй агентуудыг зэрэг (parallel) ажиллуулах замаар хугацаа хэмнэж, зөрчил үүсэх эрсдэлгүйгээр засна.

## АЖИЛЛАХ 4 ҮЕ ШАТ:

### 1. Төлөвлөлт ба Динамик Агент Үүсгэлт (Spawning Phase)
Шүүмжийн тайланг уншиж, тулгарсан согог бүрд зориулж "Мэргэшсэн Түр Агент"-уудыг тодорхойлно:
- **Агентын нэр:** Шийдэх асуудлын нэрээр нэрлэнэ (жишээ нь: `reader-font-scaler`, `bookmark-sqlite-keeper`, `card-motion-physicist`, `search-debouncer`). Frontend, Backend гэсэн ерөнхий нэр ашиглахыг ХАТУУ ХОРИГЛОНО.
- **Target Files:** Агент тус бүрийн гар хүрэх тодорхой файлуудыг хатуу заана (Scope isolation).
- **Үүрэг & Хүлээгдэх үр дүн:** Ямар алдааг яаж засвал амжилттайд тооцох шалгуур.

### 2. Хамаарлын Шинжилгээ ба Гүйцэтгэлийн Бүлэглэлт (Dependency & Concurrency Graph)
Тодорхойлсон агентуудыг файлын давхардал болон логик хамаарлаар нь 2 ангилна:
- **Batch A (Parallel Execution - Зэрэг ажиллах):**
  Өөр өөр файлууд дээр ажиллах, бие биеийнхээ өгөгдлийн бүтцээс хамааралгүй агентууд (жишээ нь: `card-motion-physicist` нь UI дээр, `search-debouncer` нь хайлтын сервис дээр зэрэг зэрэгцэж ажиллана).
- **Batch B (Sequential Execution - Дарааллаар ажиллах):**
  Нэг файл дээр зэрэг ажиллаж болохгүй, эсвэл нөгөө агентынхаа үүсгэсэн дата моделоос хамаардаг агентууд (жишээ нь: Баазад хүснэгт үүсгэж дууссаны дараа UI агент дуудагдана).

### 3. Зэрэгцээ ба Дараалсан Гүйцэтгэл (Orchestration & Execution)
1. **Зөвшөөрөл авах:** Эхлээд төлөвлөгөөгөө хэрэглэгчид доорх загвараар танилцуулна:
```text
[SPAWNED AGENTS PLAN]:
• Зэрэг ажиллах (Parallel Batch 1):
  - Agent: haptic-motion-polisher -> [theme.ts, animated_button.tsx]
  - Agent: search-debouncer -> [search_service.ts]
• Дараалж ажиллах (Sequential Batch 2):
  - 1-р алхам: reading-storage-keeper -> [schema.sql, storage_service.ts]
  - 2-р алхам: reader-ui-connector -> [reader_screen.tsx]
```

2. **Гүйцэтгэх:** 
- Parallel бүлэгт багтсан агентуудын өөрчлөлтийг нэгэн зэрэг гүйцэтгэж файлуудыг шинэчилнэ.
- Дараа нь Sequential бүлгийн агентуудыг хамаарлын дарааллаар нь засуулна.
- `// TODO` эсвэл хагас дутуу placeholder ашиглахыг хатуу хориглоно.
- **Автомат Commit:** Parallel Batch эсвэл Sequential Agent ажлаа амжилттай дуусгах бүрд Conventional Commits (`feat:`, `fix:`, `refactor:`, `style:`) стандартаар автоматаар commit хийнэ.

### 4. Шүүмж Баталгаажуулалт (Verification)
- Бүх агентууд ажиллаж дуусмагц шүүмж дээр байсан согогууд бүрэн арилсан эсэхийг шалгаж, `RESOLUTION_REPORT.md` файл үүсгэнэ.
- **Git Push Guardrail:** Бүх засвар болон commit-ууд дуусмагц хэрэглэгчид хийгдсэн commit-уудын жагсаалтыг (`git log -n ...`) харуулаад: `"Бүх засвар амжилттай хийгдэж локал Git дээр commit хийгдлээ. GitHub руу push хийх үү? (Зөвшөөрөл өгөх бол 'push хий' гэж бичнэ үү)"` гэж асуугаад ЗОГСОНО.

# Plugin: Dynamic Issue-Driven Agent Spawner

## ЗАРЧИМ
Энэхүү плагин нь урьдчилан бэлдсэн хатуу агентууд ашиглахгүй. Шүүмжид дурдагдсан асуудал бүрийг задлан шинжилж, яг тэр асуудлыг хамгийн сайн шийдэж чадах тусгай агентуудыг дүр, үүрэг, хариуцах файлуудтай нь газар дээр нь бий болгож (spawn) ажиллуулна.

## АЖИЛЛАХ 5 ҮЕ ШАТ:

### 1. Шүүмжийн Задаргаа (Critique Triage)
- Шүүмжийн тайланг уншиж, тулгарсан согогуудыг бие даасан Асуудлын Багц (Problem Clusters) болгон бүлэглэнэ.
- *Жишээ нь:* UI муу гэж ерөнхий харахгүй, "Typography & Contrast", "Book Persistence Logic", "Search Debounce Optimization" гэх мэт тусгай кластерууд болгоно.

### 2. Динамик Агент Үүсгэлт (Agent Spawning)
Кластер тус бүрд тохирсон "Мэргэшсэн Түр Агент"-уудыг автоматаар нэрлэж, даалгавар өгнө:
- **Агентын нэр:** Тухайн асуудалд зориулагдсан байх (Жишээ нь: `reading-session-manager`, `palette-contrast-fixer`, `list-physics-animator`, `auth-validator`).
- **Target Files:** Зөвхөн тэр асуудалтай шууд холбоотой тодорхой файлуудыг хариуцуулна (нэг агент бусдынхаа файл руу дур мэдэн орохгүй).
- **Goal:** Шүүмж дээрх дутагдлыг эксперт апп-ын түвшинд хүргэж засах ганцхан тодорхой зорилготой байна.

### 3. Гинжин Хамаарал & Гүйцэтгэл (Orchestration & Execution)
- Динамикаар үүссэн агентуудын аль нь эхэлж ажиллах, аль нь нөгөөгөөсөө хамааралтай (dependencies) болохыг тогтооно.
- Хэрэв Агент 1 нь дата бүтцээ өөрчлөх шаардлагатай бол эхлээд түүнийг дуусгаад дараагийн хамааралтай Агент 2-ыг дуудна.
- Бүх засварууд `// TODO` эсвэл дутуу placeholder ашиглахгүйгээр 100% бодит кодоор хийгдэнэ.
- **Автомат Commit:** Агент (sequential) эсвэл Parallel Batch ажлаа амжилттай дуусгах бүрд тогтоосон Conventional Commits стандартын дагуу автоматаар git commit хийнэ.

### 4. Шүүмж Хангалтын Баталгаажуулалт (Critique Verification)
- Бүх динамик агентууд ажлаа дуусмагц анхны шүүмж дээр дурдагдсан алдаа бүрийг тулган шалгаж, "Шийдэгдсэн / Шийдэгдээгүй" статустай `RESOLUTION_REPORT.md` тайлан үүсгэнэ.

### 5. Git Guardrail & Push Зөвшөөрөл (Push on User Approval)
- Бүх засвар болон commit-ууд дуусмагц хийгдсэн commit-уудын жагсаалтыг (`git log -n ...`) хэрэглэгчид дэлгэрэнгүй харуулна.
- Хэрэглэгчээс GitHub руу push хийх зөвшөөрөл асуугаад ЗОГСОНО.
- Зөвхөн хэрэглэгчээс зөвшөөрөл авсан үед л push хийнэ.

# Git Workflow Integration (Commit Automatically, Push on Approval)

## 1. АВТОМАТ COMMIT (Automated Commits):
Агентууд ажлаа амжилттай дуусгах бүрд дараах дүрмийн дагуу АВТОМАТААР git commit хийнэ:
- **Parallel Batch дуусах үед:** Тухайн зэрэгцээ ажилласан бүлгийн бүх өөрчлөлтийг багцалж нэг тодорхой commit үүсгэнэ.
  * Жишээ: `feat(ui,search): parallel update for haptic motion and search debouncer`
- **Sequential Agent тус бүр дуусах үед:** Өөрийн хариуцсан ажлыг дуусмагц тусдаа бие даасан commit хийнэ.
  * Жишээ: `fix(storage): resolve bookmark persistence in sqlite`
- **Conventional Commits стандарт:** Commit мессежүүд нь `feat:`, `fix:`, `refactor:`, `style:` гэсэн стандарттай, ямар өөрчлөлт орсон нь тодорхой байна.

## 2. ХАТУУ ХОРИГЛОХ ЗҮЙЛ - PUSH ДҮРЭМ (Strict Push Guardrail):
- **АВТОМАТААР GITHUB РУУ PUSH ХИЙХИЙГ ХАТУУ ХОРИГЛОНО.**
- Агент өөрөө дур мэдэн `git push` комманд ажиллуулахгүй.
- Бүх засвар болон commit-ууд дуусмагц хэрэглэгчид хийгдсэн commit-уудын жагсаалтыг (`git log -n ...`) харуулаад:
  `"Бүх засвар амжилттай хийгдэж локал Git дээр commit хийгдлээ. GitHub руу push хийх үү? (Зөвшөөрөл өгөх бол 'push хий' гэж бичнэ үү)"` гэж асуугаад ЗОГСОНО.
- Зөвхөн хэрэглэгч "push хий", "тийм", "зөвшөөрч байна" гэж тушаасан үед л `git push origin <current-branch>` коммандыг ажиллуулна.

## ГҮЙЦЭТГЭЛИЙН ТӨЛӨВЛӨГӨӨНИЙ ЗАГВАР:
Ажиллаж эхлэхдээ шууд код өөрчлөхгүй, эхлээд хэрэглэгчид ямар агентууд томилсноо дараах форматаар танилцуулна:

| Агентын Нэр (Agent Role) | Шийдэх Асуудал (Target Problem) | Хариуцах Файлууд (Target Files) | Хамаарал (Depends On) | Commit Төлөвлөгөө |
| :--- | :--- | :--- | :--- | :--- |
| `[агентын-нэр]` | [Шүүмж дээрх тодорхой согог] | `[хариуцах файлуудын зам]` | [Хамааралтай агент эсвэл 'Байхгүй'] | `fix(...): ...` |
